### 2. ARCHITECTURE DU FLUX D'EXÉCUTION (LE PONT SOTA)

```mermaid
sequenceDiagram
    autonumber
    participant UI as Dashboard Streamlit (Onglet 6)
    participant Engine as KanbanEngine
    participant DB as SQLite WAL (telemetry.db)

    participant Gem as Gemini Web App (Cloud SOTA)
    participant Queue as Vault_Data/03_Kanban_Specs/AGENT_QUEUE.md
    participant Agent as Agent Codeur (CLI / IDE)

    Note over UI,DB: 1. CAPTURE & ARBITRAGE D'IDÉE
    UI->>DB: Création de tâche (status: 'radar' ou 'needs_spec')
    UI->>UI: Arbitrage en 1 clic : [Valider ➔ Spec] ou [🧊 Frigo]

    Note over UI,Gem: 2. ALLER : CONTEXT-PACK SOTA
    UI->>Engine: build_sota_context_pack_prompt(task_id)
    Engine->>DB: Métadonnées tâche + projet
    Engine->>Engine: Scan arborescence repo (arborescence épurée sans bruit)
    opt Ollama actif
        Engine->>Lance: Recherche k-NN (top_k=3) + purge immédiate VRAM
    end
    Engine->>Clip: Copie du prompt SOTA assemblé
    UI->>Gem: L'utilisateur colle le prompt dans un chat Gemini Web

    Note over Gem,UI: 3. RETOUR : INGESTION DE LA SPÉCIFICATION
    Gem-->>Clip: Gemini Web génère le Markdown (Changelog + Prompt Agent)
    UI->>Engine: attach_spec_to_task(clipboard_content)
    Engine->>Engine: Sauvegarde 03_Kanban_Specs/{project_id}/{task_id}_{slug}.md
    Engine->>DB: status='ready_for_agent' + lien spec_file_path
    Engine->>Queue: Mise à jour AGENT_QUEUE.md

    Note over Queue,Agent: 4. EXÉCUTION PAR L'AGENT CODEUR
    Agent->>Engine: python run_exocortex.py --next-task
    Engine->>DB: status='in_progress'
    Engine-->>Agent: Injection Section 2 (Prompt Agent Codeur pur)
    Agent->>Agent: Exécution & validation pytest
    Agent->>Engine: python run_exocortex.py --complete-task <TASK_ID>
    Engine->>DB: status='done'
    Engine->>Queue: Retrait de la file active & archivage
```
